# CyKit Extension

A Chrome extension (Manifest V3) with quality-of-life tweaks for Cybozu products —
kintone, Garoon, and the cybozu.com portal.

**Feature 1 — Font.** Replaces kintone's default font across the whole UI with a
bundled, more readable webfont, and scales text size and weight.

**Feature 2 — Schedule.** Shows your Garoon calendar on kintone pages. Opt-in;
it is the only feature that contacts a server.

**Feature 3 — Branch locks.** Warns on a pull request when the branch it targets
is closed for merging, reading the windows from a Garoon group calendar.

**Feature 4 — GitHub.** Adds a Copy button to pull request and issue pages that
puts the title, the canonical link, or both on the clipboard.

## Setup

```sh
corepack enable
pnpm install
pnpm fonts     # downloads the bundled woff2 files into public/fonts/
pnpm icons     # generates public/icons/*.png
pnpm build     # typecheck + build into dist/
```

Then load it:

1. Open `chrome://extensions` (Edge: `edge://extensions`, Arc: `arc://extensions`)
2. Turn on **Developer mode**
3. **Load unpacked** → select the `dist/` folder

While developing, `pnpm watch` rebuilds both bundles on change. Content-script
changes need a reload of the extension **and** the kintone tab; popup changes
only need the popup reopened.

## Scope: kintone vs Garoon

One Cybozu host serves several products, so the manifest globs cannot tell them
apart. They are distinguished per page by the first path segment
(`src/shared/scope.ts`):

| path | product |
| --- | --- |
| `/k/123/`, `/k/admin/…`, `/k/m/…`, `/k` | `kintone` |
| `/g/schedule/index.csp`, `/g/mobile/…`, `/g` | `garoon` |
| `/portal/`, `/login`, `/cybozu-admin/`, `/o/…` | `other` |

The trailing slash in the prefix test matters: `/gadget/foo` must not read as
Garoon, and `/kintone/x` must not read as kintone.

**Scope is per feature, not global.** It lives on the feature's own settings
(`font.scope`) and its checkboxes sit in that feature's panel under **Apply on**,
so each feature can be pointed at different products. All three products are on
by default.

The content-script globs stay broad on purpose. Each feature calls
`isInScope(font.scope, location.pathname)` at apply time, so flipping a checkbox
takes effect on open tabs without touching host permissions. Out of scope a
feature behaves exactly as if disabled — `applyFont` writes empty CSS,
`applyFontMetrics` uses neutral metrics — which makes a page that was styled a
moment ago clean itself up.

Because `all_frames` is on, each frame is judged by its own path. Plugin iframes
under `/k/plugin/…` therefore stay in kintone's scope.

## How the font feature works

It is two content-script features sharing one settings object: `font.ts` swaps
the font-family in CSS, `font-metrics.ts` scales size and weight in JS.

### Family (`src/content/features/font.ts`)

`src/content/features/font.ts` injects a single `<style id="cykit-font">`
element and rewrites its contents whenever settings change — no page reload
needed. The CSS is generated by `src/shared/css.ts`:

- `@font-face` rules pointing at `chrome-extension://…/fonts/*.woff2`, declared
  as `web_accessible_resources` so kintone's CSP cannot block them.
- One `*:not(…) { font-family: … !important }` rule.

Three details matter:

- **`pre` and `tt` are not treated as code.** Garoon puts message bodies in
  `pre.format_contents` and attachment names in `tt`, so mapping those tags to
  the monospace font turned whole pages of prose into a code face. A conforming
  code block is `<pre><code>`, which the `code` selector already covers, and
  dropping `pre` costs nothing else — whitespace comes from `white-space`, not
  from the font. Editors do not use `code` at all, so CodeMirror (kintone's
  JS/CSS customisation screen, `pre.CodeMirror-line`), ACE and Monaco are
  matched by class instead. Those class selectors anchor to a token boundary,
  `[class^="ace_"], [class*=" ace_"]`, so `ace_` cannot also match `space_left`.
- **Icon fonts are excluded, not overridden.** Icon glyphs come from a
  `font-family` set on the element itself, so an `!important` override would
  turn them into tofu. `revert` is not a fix — it would drop the site's own
  declaration too — so those elements are kept out of the selector entirely
  (`i`, `[class*="icon" i]`, `[class*="fa-" i]`, `svg`, …).
- **Injected at `document_start` and re-asserted on `load`.** kintone appends
  stylesheets after the document starts parsing; the style element is moved back
  to the end of `<head>` so later rules of equal importance don't win.

### Size and weight (`src/content/features/font-metrics.ts`)

This one cannot be CSS. `* { font-size: 1.1em }` compounds once per DOM level —
kintone nests ~20 deep, so 1.1²⁰ ≈ 6.7× — and a fixed px value flattens every
heading and label to one size. Same for `font-weight`.

So the feature measures the tree and then rewrites only the elements that
**declare** their own size or weight. Elements that merely inherit are left
alone and pick up their ancestor's new value, which preserves kintone's
hierarchy exactly. Reads and writes are separate passes so style is resolved
once, not per element.

Verified in headless Chromium (`13px` body, nested `px`/`em`/inherited nodes):

| node | declares | before | after ×1.2, min 12, +200 |
| --- | --- | --- | --- |
| `#a` | `16px` | 16.00 / 400 | **19.20** / **600** |
| `#b` | — inherits | 16.00 / 400 | 19.20 / 600 |
| `#c` | `1.5em` | 24.00 / 400 | **28.80** / 600 — stays 1.5× of `#a` |
| `#e` | `10px` | 10.00 / 400 | **12.00** / 600 — floored, not 12.0×1.2 |
| `#z` | `font-size: 0` | 0.00 | **0.00** — floor skipped |
| `h1` | UA `2em`, `700` | 26.00 / 700 | 31.20 / **700** — weight clamped |
| `b` | UA `bolder` | 13.00 / 700 | 15.60 / **700** — pinned |
| `i.icon` | `14px` | 14.00 / 400 | **14.00 / 400** — untouched |

Four details that each cost a bug:

- **`font-weight` is written even when the value doesn't change.** `<b>` and
  `<strong>` use `font-weight: bolder`, which re-resolves against the parent, so
  a body bumped to 600 drags them from 700 to **900** and Chrome synthesises a
  fake bold. Writing the resolved number pins them.
- **Icon elements get their original weight pinned.** They are excluded from the
  scaling, but they still *inherit* weight, so the bump would fake-bold glyphs
  from single-weight icon fonts.
- **Weight is clamped to 700**, the top of the bundled variable fonts' range —
  no synthetic weights, and bold headings don't outrun body text.
- **`font-size: 0` only gets the scale, never the floor.** It is a
  kill-inline-block-whitespace trick still used in parts of kintone; flooring it
  to 12px would push that whitespace back into the layout.

Original inline `style` values are saved in `data-cykit-fs` / `data-cykit-fw` and
restored verbatim when the feature is turned off.

New DOM is handled by a `MutationObserver` (120 ms debounce, and past 40 roots
in one batch it does a single full pass instead of deduping them).

Known limits:

- A node inserted **after** the first pass that declares a *relative* size
  (`1.2em`, `120%`) under an already-scaled ancestor gets scaled twice. kintone's
  own CSS is px throughout, so this is rare in practice.
- The overrides are inline `!important`, so if kintone later changes an
  element's class to give it a different size, our value stays. Only `childList`
  is observed, not attributes.

### Japanese text

Japanese glyphs come from the OS, not from the extension: Noto Sans JP alone is
~3 MB spread over 124 subset files. Every font stack in `src/shared/fonts.ts`
therefore ends with a Japanese fallback chain (Hiragino Sans → Yu Gothic →
Noto Sans JP → Meiryo). Bundled Latin fonts cover Vietnamese via the
`vietnamese` and `latin-ext` subsets.

### Vietnamese

Every bundled family ships its `vietnamese` and `latin-ext` subsets, so stacked
diacritics (`ế ộ ữ ằ`, and the harder uppercase `Ế Ộ Ữ Ằ`) render without tofu.
**Be Vietnam Pro** is the one drawn for Vietnamese specifically and has the most
even diacritic placement.

Be Vietnam Pro is **not** a variable font, so `fetch-fonts.mjs` requests its
weights one at a time (400/500/600/700). Without that the Weight feature would
ask for 500 and get a synthetic bold. Verified in headless Chromium — the four
weights render at four distinct widths (432.41 / 435.41 / 438.89 / 442.05 px for
the same string), which a synthesised bold would not do.

`font-stretch` is carried through from the Google Fonts CSS. Families with a
`wdth` axis (Open Sans, Roboto, Noto Sans) declare it, and dropping it would
leave the `@font-face` describing a font it does not match.

Total bundled font payload: ~1.75 MB across 63 files.

## Licences

The fonts are redistributed, so their licences travel with them. `pnpm fonts`
pulls each family's licence from `github.com/google/fonts` into
`public/fonts/licenses/<id>.txt` and writes an index at
`public/fonts/licenses/README.txt`. The fetch **fails loudly** if a licence
cannot be found, so a font can never be bundled without one.

All nine families are OFL 1.1, verified from the shipped licence files. Three
carry a Reserved Font Name — IBM Plex Sans (`Plex`), Source Sans 3 (`Source`)
and Lexend (`RevReading Lexend`). That clause only binds *modified* versions,
and we satisfy it two ways: `fetch-fonts.mjs` writes Google's bytes verbatim
without touching the font, and every `font-family` we declare matches the
original name exactly. Never rename a family in `src/shared/fonts.ts`.

The files are Google's subsets (latin, latin-ext, vietnamese), so they are
technically derivative — but the subsetting is Google's, served under the
original names, which is how every self-hosted Google Fonts deployment works.

The extension's own code is MIT and separate from the fonts.

## The GitHub feature

`src/content/features/github-copy.ts` puts a **Copy** button next to the title
on `/pull/N` and `/issues/N` pages. Clicking it opens a menu offering *Title and
link*, *Title only* or *Link only*. The first gives:

```
PROJ-142: Cache the weekly schedule query
https://github.com/example-org/example-app/pull/248
```

The menu follows Primer's ActionMenu shape — a 12px overlay, a header naming
the item being copied, then rows with a leading icon, a label, and a preview of
what lands on the clipboard. "Title and link" previews as two lines because it
copies two lines; the URL drops its scheme so more of the path survives the
ellipsis.

**Every class the widget creates is namespaced, and its stylesheet opens with a
reset.** A span of `class="label"` is not ours on github.com — GitHub has its
own `.label` rule, and it drew each row's title inside a bordered pill. The
namespace stops the collision; the reset handles the other direction, where
GitHub styles bare `button`/`ul`/`header` elements and anything we create
inherits rules we never asked for. Both halves are covered by regression tests
that load deliberately hostile CSS and assert the computed styles.

Mechanics worth knowing:

- It is `position: fixed`, placed from the button's bounding rect rather than
  absolutely inside the wrapper, because an ancestor with `overflow: hidden` in
  GitHub's header would otherwise clip it. The trade-off is that it does not
  follow the page, so scrolling closes it.
- It closes on Escape, an outside `pointerdown`, a second click on the button,
  scroll, resize, and when the feature is switched off. Every one of those
  paths unbinds the listeners it added, so nothing stays attached to `document`
  once the menu is gone.
- Arrow keys move between rows and wrap at both ends, which is what the `menu`
  role promises.

Four things this has to get right:

- **Never match on class names.** github.com is React with CSS modules, so the
  heading carries `PullRequestHeader-module__inlineTitle__czbud` — the hash
  changes with every deploy. The anchor is `h1[data-component="PH_Title"]`,
  Primer's own contract, with `.js-issue-title` kept as a fallback for older
  GitHub Enterprise and `document.title` parsing as a last resort.
- **Strip the screen-reader text.** The heading also contains
  `<span class="sr-only"> - #248</span>`, which would otherwise land in the
  copied title. The node is cloned before stripping so the page is untouched.
- **Normalise the URL.** `parseIssuePath` rebuilds the link from
  `owner/repo/kind/number`, so copying from the Files or Commits tab — or with
  a `#issuecomment-…` anchor — still yields the plain pull request URL.
- **Survive client-side navigation.** GitHub never reloads, so there is no
  `load` event to hang this on. A debounced `MutationObserver` re-places the
  button, and the click handler re-reads the title rather than capturing it.

The clipboard write uses `navigator.clipboard.writeText` — allowed from a
content script because the click is a user gesture — falling back to a hidden
textarea and `execCommand('copy')`.

### Host scope

Adding GitHub widened the content-script matches beyond Cybozu, so
`detectProduct` is now host-aware and returns `github` for github.com.
`isInScope` rejects that product outright rather than defaulting it, which is
what keeps the font override from following the content script onto GitHub.
`web_accessible_resources` for the fonts is deliberately *not* opened to
github.com.

## The Schedule feature

`src/content/features/schedule.ts` puts a floating card on `/k/` pages showing
the signed-in user's Garoon diary.

**It answers a question rather than listing rows.** A real Garoon day is mostly
attendance markers — `[Make Up]`, `[Rest all day]`, `[Late]`, `[Go out]` — which
are all-day entries for the whole team. Counting them gave "9 today" when only
three were meetings, and what you actually want at a glance was buried in the
middle. So the card leads with a headline (what is running, or what is next and
in how long), counts meetings rather than entries, dims what has finished, and
rolls the all-day markers into one expandable line.

Times update on a 30-second tick; the same timer refetches once the five-minute
cache expires. Rows link to the event in Garoon.

**Why this needs no new permission.** kintone and Garoon are served from the
same host, so `GET /g/api/v1/schedule/events` from a content script on a `/k/`
page is same-origin: the session cookie rides along, and `host_permissions`
never enters into it. Moving this to the popup would change that — the popup is
an extension page, the call becomes cross-origin, and the added permission
would disable the extension for every existing user until they accepted it.

Details that matter:

- **Session auth, reads only.** Garoon's docs require an `X-Requested-With`
  header for session-authenticated calls, and a CSRF token *for writes*. This
  never writes, so no token is needed and none is obtained — which also avoids
  reaching into the page's JS context from an isolated world.
- **`target` is omitted deliberately.** The API then defaults to the user
  running the request, which is exactly "my schedule" and avoids having to
  discover a user id.
- **Off by default.** It is the only feature that talks to a server, so an
  update does not quietly switch it on.
- **Failure is silent.** Signed out, Garoon not enabled on the host, network
  down — each returns no card rather than a broken one. Nothing is allowed to
  throw into someone's kintone page.
- **The card is `position: fixed` and anchors to nothing.** Injecting into
  kintone's own markup would mean matching its class names, which move between
  versions.
- **Top frame only.** The content script runs with `all_frames: true` because
  the font features need it, but kintone's portal embeds portlets in iframes —
  and a fixed-position card inside an iframe anchors to *that* iframe's
  viewport, so the portal drew one card per frame. Guarded with
  `window.self === window.top`; comparing the references is safe cross-origin
  even though reading through them is not.
- Responses are held in memory for five minutes and never written to storage.
- **Event links are constructed, not returned.** The API carries no URL for an
  event, so rows point at Garoon's long-standing
  `/g/schedule/view.csp?event=<id>`.
- **`[start, end)` is half-open.** A meeting ending at 14:00 is over at 14:00 —
  otherwise the headline keeps advertising a meeting that just finished while
  the next one is the thing you need.

`src/shared/garoon.ts` holds the parts worth testing on their own: RFC 3339
with the local offset, day windows, defensive parsing (an event with no usable
start is dropped, unknown fields ignored), and bucketing into days — including
the midnight boundary, where 23:59 and 00:01 must land on different days.

## The branch-lock feature

Garoon carries windows like `🔒 [main] Sep/24 19:00 - Sep/28 12:00 (JST)` on a
group calendar, during which that branch must not be merged. Nobody on GitHub
can see them without going to look, so `src/content/features/branch-lock.ts`
puts the answer on the pull request, directly above the merge box.

**Why this one needs a service worker and a permission.** Chrome is explicit
that "cross-origin requests are always treated as such in content scripts, even
if the extension has host permissions" — so unlike the kintone widget, which is
same-origin, this cannot be done from the page. `src/background.ts` makes the
request instead, which requires host access to the Cybozu address. That access
is declared as `optional_host_permissions` and requested from the popup, so
installing or updating never shows a new warning and never disables the
extension; only someone switching this on sees a prompt.

Borrowing an already-open Cybozu tab would have avoided the permission
entirely. It was rejected: a colleague with no such tab would see no warning at
all, which is worse than having no feature, because people come to rely on it.

**Every outcome is shown, including failure.** A banner that silently fails to
appear looks exactly like "the branch is open", and someone would merge on
that. So `open`, `could not check`, and `not configured` each render their own
line rather than nothing.

Details:

- The target branch is read from the *href* of the first
  `a[data-component="BranchName"]` (`/owner/repo/tree/<branch>`), not its text —
  the text carries an owner prefix (`react:main`) and branch names may contain
  slashes, so splitting the text is ambiguous while the href is not.
  `.base-ref` remains as a fallback for older GitHub Enterprise.
- The banner is placed in `[data-testid="mergebox-partial"]`, with a chain of
  fallbacks ending at `main`: appearing somewhere worse beats not appearing.
- `src/shared/lock.ts` parses the titles. The 🔒 is **not** required — a window
  typed without it would otherwise be missed silently, and for a safety feature
  a false positive on a branch nobody targets is much cheaper than a miss.
- Responses are cached for two minutes, shorter than the schedule's five: a
  stale "open" here is the expensive kind of wrong.

## Layout

```
popup.html                     popup entry (Vite multi-page)
public/manifest.json           MV3 manifest, copied to dist/ verbatim
public/fonts/                  generated by pnpm fonts (woff2 + licenses/)
public/icons/                  generated by pnpm icons
src/content/index.ts           content-script entry, feature registry
src/content/features/font.ts   font-family override (CSS)
src/content/features/font-metrics.ts  size + weight scaling (JS)
src/content/features/github-copy.ts   GitHub copy button
src/shared/github.ts           URL parsing + clipboard text, DOM-free
src/popup/panels.ts            sidebar menu registry — one entry per feature
src/popup/App.tsx              popup shell: sidebar + active panel
src/popup/FontPanel.tsx        the Font panel
src/shared/scope.ts            kintone / Garoon / other detection from the path
src/shared/garoon.ts           schedule API URLs + response shaping, DOM-free
src/shared/lock.ts             branch-lock titles, lock state, PR base branch
src/background.ts              service worker: the one cross-origin fetch
src/content/features/branch-lock.ts   merge warning on pull requests
src/content/features/schedule.ts      Garoon schedule card on kintone
src/shared/css.ts              stylesheet generation
src/shared/fonts.ts            font catalogue + fallback stacks
src/shared/storage.ts          chrome.storage.sync wrapper + defaults
src/shared/types.ts            shared types
```

Two Vite builds, because MV3 content scripts are classic scripts and cannot be
ES modules:

- `vite.config.ts` → `popup.html` + assets (ESM, code-split)
- `vite.config.content.ts` → `content.js` (single IIFE, `emptyOutDir: false`)

## Adding a feature

1. Add its settings to `Settings` in `src/shared/types.ts` and to
   `DEFAULT_SETTINGS` in `src/shared/storage.ts` (add a merge line in
   `withDefaults` — nested objects such as `scope` need their own merge, or a
   stored value written by an older version arrives with missing keys). Give it
   its own `scope: Scope` if it should be limited to some products.
2. Create `src/content/features/<name>.ts` exporting
   `apply(settings: Settings): void`. It **must be idempotent**, and it **must
   undo itself when disabled** — it is called on load, on every settings change,
   again on `load`, and with everything switched off on out-of-scope pages.
3. Register it in the `FEATURES` array in `src/content/index.ts`.
4. Write `src/popup/<Name>Panel.tsx` taking `PanelProps`, and add one entry to
   `PANELS` in `src/popup/panels.ts`. That is the whole popup change — the
   sidebar menu, the active-state dot and the routing all read from that array.

## Supported hosts

`*.cybozu.com`, `*.kintone.com`, `*.cybozu.cn`, `*.kintone.cn`,
`*.cybozu-dev.com`. Custom kintone domains would need
`optional_host_permissions` plus `chrome.scripting.registerContentScripts`;
not implemented yet.

## Releasing an update

**Bump once per upload, not once per change.** The version in
`public/manifest.json` tracks what the store has published, so it should only
move when a package is actually going to be uploaded. Several commits landing
between releases all ship under the same next version.

```sh
pnpm bump          # once, when you are about to upload
pnpm package       # builds, zips dist/, and checks the archive
```

While iterating, run `pnpm package` on its own — it rebuilds the zip at the
current version, overwriting the previous file.

Then upload `cykit-<version>.zip` in the developer dashboard and submit. The
listing text, images and permission justifications persist between updates, so
only the package changes.

Two things worth planning around:

- **Adding a permission disables the extension for existing users** until each
  of them accepts the new prompt. If more hosts are coming — a GitHub
  Enterprise domain, say — add them in one release rather than several.
- The store rejects a version it has already seen, which is why `pnpm bump`
  exists: it moves `public/manifest.json` and `package.json` together, and the
  zip is named after the version so a forgotten bump shows up before upload.
